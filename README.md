# Roostr iOS

The iPhone body for the Roostr engine. All note semantics (protobuf codec,
content addressing, replay, queries, mutation planning, NIP-44, the sync
session and outbox) run in the Odin engine from the sibling `glonOdin`
repository, linked here as `Vendor/Glon.xcframework`. Swift owns only what
the device must: the bridge actor, relay WebSocket, signing, SQLite, Keychain,
the sync loop and the SwiftUI shell.

## Layout

```
Vendor/Glon.xcframework   Odin engine: ios-arm64, ios-arm64-simulator, macos-arm64 static slices
Vendor/glon-core.json     compiler + sha256 of every Odin source the framework was built from
Sources/GlonCore/         GlonCore actor: single-flight JSON ABI over the static library
Sources/RoostrSync/       Host for the engine: Contracts (shared types), Nostr keys/signing, Relay (NIP-01 WebSocket), SQLiteChangeStore, Identity (Keychain), SyncEngine (session + outbox loop), Backend (objects/mutations the UI consumes)
Sources/RoostrUI/         SwiftUI shell shared by both platforms: AppModel, identity gate, object list, object view, RoostrApp scene
Sources/RoostrMac/        macOS runner (`roostr-mac`) for the same UI without a simulator
Tests/GlonCoreTests/      golden fixtures shared with glonOdin/core and the website: codec_fixtures.json (protobuf codec, content addressing), wire_fixtures.json (NIP-44, blinded tags, sealing, address verification), authority_fixtures.json (shared-space authority gate, vanish ledger); SyncSessionTests mirrors glonOdin/core/sync_session_test.odin (receive-side reassembly, cursor, replay bookkeeping; outbox order, dedupe, rotated-key rule, backoff and sealing on first send) with events sealed by the engine itself
Tests/RoostrSyncTests/    host tests: signing/verify against nostr-tools fixtures, store, relay, sync loop
App/                      iOS entry (`RoostrIOSApp`), project generated by XcodeGen from project.yml
```

## Engine

Rebuild the framework after changing `glonOdin/{abi,core,native}`; commit both
artifacts together, as the website does with `engine.wasm`:

```sh
# glonOdin repository (needs Odin and Xcode command line tools)
node build-xcframework.mjs            # writes ../RoostrIOS/Vendor/
```

The ABI is `core_init` once, then per call: `core_reserve(n)` → write UTF-8 JSON
`{method, payload}` → `core_execute()` → read `core_response_pointer/length` →
`core_reset(0)`. `GlonCore.shared.call(method, payload)` does exactly that and
throws `GlonError.engine(message)` for `{error}` envelopes. The engine is not
thread-safe; never call the C symbols outside the actor.

## Verify

```sh
swift test                             # macOS slice: engine parity, store, signing, sync loop
brew install xcodegen && xcodegen      # Roostr.xcodeproj for the app shell
```

`RelayTests` and `LiveSyncTests` run against a local relay when one listens on
`ws://127.0.0.1:7799` (`ROOSTR_TEST_RELAY` overrides; they skip otherwise):

```sh
# RoostrRelay repository
odin build src -o:speed -out:/tmp/roostr-relay && PORT=7799 DB_PATH=/tmp/relay-test.db /tmp/roostr-relay
```

Running on a simulator needs the iOS platform installed in Xcode
(`xcodebuild -downloadPlatform iOS`).

## Run on macOS

```sh
swift run roostr-mac                                   # default relay wss://roostr-relay.fly.dev
ROOSTR_RELAYS=ws://127.0.0.1:7799 ROOSTR_DB=/tmp/roostr.sqlite swift run roostr-mac
```

`ROOSTR_RELAYS` is a comma-separated relay list; `ROOSTR_DB` overrides the
database path (default `~/Library/Application Support/Roostr/roostr.sqlite`).
The identity lives in the login Keychain (`app.roostr.identity`); "Log out"
forgets it and deletes the local database, as the website does. The unsigned
developer runner can keep the key in memory instead (`ROOSTR_IDENTITY=memory`,
optionally prefilled with `ROOSTR_SECRET=<hex>`).
